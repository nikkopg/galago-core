<objective>
Fix the operator-facing pause detail so an instrument "no plate detected" sentinel (`detectedPlateID: -1`) renders as "found none" instead of "found -1", and lock the behavior with unit tests.

Observed at planning time (live read of the files):
- `controller/components/runs/pausePrompt.ts` lines 194-209: private `describeWrongDetectionEntry` sets `found` to "none" only when `detectedRaw` is `null`, `undefined` or `""`; every other value goes through `String(detectedRaw)`, so the number `-1` prints as "found -1".
- The function is reached only through exported `describePauseDetail` (line 214), whose sole production consumer is `controller/components/runs/ToolPausedModal.tsx` line 54. No consumer change is needed.
- `controller/test/pausePrompt.test.ts` (440 lines, 15 passing tests) has a `describe("reason and detail edge cases", ...)` block starting at line 388 whose `it("describePauseDetail covers known and unknown shapes", ...)` (line 397) is the pattern to follow.

Choice on the string "-1" (Claude's discretion, stated here and in a code comment): treat BOTH the number `-1` and the exact string `"-1"` as the no-plate sentinel. Reason: `detail` is untyped JSON from the instrument (typed `unknown` here), so a stringified sentinel is plausible and no real plate ID is "-1". Matching is exact (`=== -1` or `=== "-1"`) — no trimming, no "any negative" rule — so genuine IDs, including `0` and other negatives such as `-2`, still render verbatim and nothing real is hidden from the operator.

Purpose: the operator decides every physical recovery action from this prompt (PROJECT core value). "found -1" reads like a real plate ID and can mislead that decision; "found none" is accurate.
Output: patched `describeWrongDetectionEntry` plus new unit cases in `controller/test/pausePrompt.test.ts`.
</objective>
