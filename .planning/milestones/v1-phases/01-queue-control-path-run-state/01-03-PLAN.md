<objective>
Report the running tool's live run state to the run page. A server-side poller calls the running
controllable step's tool `getStatus` every 2 s. `commandQueue.runState` returns a stable envelope
built from the cached reply and never triggers gRPC itself. The poller is independent of the queue's
`modalState`/`UIMessage` plumbing, and a failed or malformed poll shows "unknown" and keeps
retrying.

Purpose: QUE-04, plus the run-state half of QUE-05 (the heartbeat half is plan 01-04). It implements
D-11, D-12, D-13, D-14 and D-17. The envelope carries queueId, so Phase 2 can correlate it with the
queue's step list. This is the Phase 1 answer to the ROADMAP's Pitfall 9 research flag; the combined
run-page query is deferred to Phase 2 per CONTEXT. Before QUE-06 regenerates the interfaces,
`extractRunState` reads `run_state` defensively (D-13); plan 01-05 switches it to the typed field.

Output: `controller/server/runState.ts` (new), the poller lifecycle in the busy loop's tool-step
bracket, the `runState` getter and tRPC query, and `controller/test/runState.test.ts`.
</objective>
