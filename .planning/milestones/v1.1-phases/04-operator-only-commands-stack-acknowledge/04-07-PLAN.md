<objective>
Close UAT gap G-04-7: tRPC `run.create` must map `OperatorOnlyCommandError` to BAD_REQUEST with the refusal's
own message on a live `next dev` server, and the same must hold for the other three mapped errors.

Root cause (binding, from .planning/debug/run-create-operator-only-500.md, confirmed by differential repro and
an identity probe): `server/routers/run.ts` classifies errors by class identity against its own module's
classes, but `createFromProtocol` runs on `RunStore.global`, a singleton pinned on
`global.__global_run_store_key` by whichever module copy created it first. Next dev 13.1.2 purges the server
require cache after every compile, so the router is re-evaluated with new error classes while the stale store
keeps throwing the old ones; every branch misses and `throw e` becomes INTERNAL_SERVER_ERROR (500). Production
`next start` is not affected (verified 400/404), but every dev session after the first recompile is, and the
same defect hits NOT_FOUND, the generation-failed branch and the params-invalid branch.

Fix route: classify by error `name` through small exported guards that sit next to each class. This follows
two existing precedents: the REST handler `pages/api/runs/index.ts` already switches on `e.name`, and tRPC
10.9's own `getTRPCErrorFromUnknown` detects TRPCError by name for the same reason. The store stays on
`global`: `CommandQueue.global` holds `new CommandQueue(RunStore.global)`, so moving the store off `global`
would split the runs Map from the queue's reference.

Purpose: OPR-04's visible refusal at run creation (verification truth 4) must hold in the dev server the
operator and UAT use, not only in a single-module-graph unit test.

Output: a regression test file that reproduces the dev purge with `vi.resetModules()` (RED first), four
name-based guards, the router and store rethrow list switched to them, and the UAT test 7 retest as the human
check.

Gap-closure note: the phase tracer was 04-01/04-02. Task 1 is this plan's end-to-end slice for the reported
branch (stale store -> refusal thrown -> fresh router -> BAD_REQUEST); Task 2 expands to the other three
branches and the store's own rethrow list.

## Resolved choices (recorded, not silent)

- **Name-based guards, not a Symbol brand or a store rewrite:** the guards match the REST handler and tRPC's
  own approach, change no runtime state, and leave `RunStore.global` / `CommandQueue.global` exactly as they
  are. Each guard is `e instanceof Error && e.name === "<ClassName>"`. The builtin `Error` is one per realm, so
  it is the same object across module copies; only the custom classes differ.
- **The store's own rethrow list switches too:** inside one module copy, class identity still holds today, but
  converting it as well leaves no class-identity classification anywhere on the run-create path. The
  generic-error wrap that uses the builtin Error check stays.
- **Spoofing posture:** only server code reaches this catch (`createFromProtocol`, `upsertParameterVariables`,
  the router's own throw). No client-controlled value sets an error name, and a mismatch would only change
  which TRPC code a server error maps to.
