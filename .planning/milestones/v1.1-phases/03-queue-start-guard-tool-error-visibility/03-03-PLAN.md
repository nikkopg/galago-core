## Deviations from CONTEXT wording (recorded, not silent)

- **D-06 data source: `commandQueue.commands`, not `getAll`.** D-06 says the counts come from the
  `getAll` data the component already polls. Research reproduced that `getAll` (`commands.all()`)
  returns dequeued rows: after an accepted abort, a FAILED row that will never run again is still in
  `getAll`. Counting from it would promise a retry that does not happen. The modal therefore adds
  `trpc.commandQueue.commands.useQuery({}, { refetchInterval: 1000 })` (existing procedure, joined to
  the queue; no server change). The existing `getAll` query stays for `hasCommandsToClear` and the
  spinner (research Pitfall 2, Open Question 2, UI-SPEC UA6).
- **D-06 STARTED rows: counted, but on their own line.** D-06 lists "STARTED if any" among counted
  rows. Per UI-SPEC S1 (UA5, research A6) a STARTED row is shown as
  "{S} step(s) still running. A Start is ignored until it ends." and is not part of "will run", because
  03-01's guard ignores a Start while a step is in flight.
- **Copy (Claude's discretion, UI-SPEC UA7):** singular/plural ("1 queued step", "3 queued steps",
  "1 run", "2 runs") instead of the literal "step(s)". With N = 1 and F = 1 the retry line reads
  "It failed before and will be retried first." When only STARTED rows exist (N = 0, S >= 1) the
  modal shows the still-running line and no "The queue is empty." line.
