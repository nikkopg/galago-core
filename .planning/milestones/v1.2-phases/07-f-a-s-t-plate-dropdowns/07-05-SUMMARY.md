## Frozen get_plates contract (galago-tools d53da53)

Sources read at the SHA: `tools/fast/server.py`, `tools/tests/fast_test.py`, `interfaces/tools/grpc_interfaces/fast.proto`.

**PLT-01 evidence (check 3).** `tools/tests/fast_test.py`, class `TestGetPlatesOverGrpc(_RealModeGrpcTestCase)`, test `test_get_plates_answers_while_a_transfer_holds_the_tool_busy`. It starts a blocked Transfer (`self._start_blocked_transfer()`), asserts the tool health is `BUSY` and `_motion_lock.locked()`, then calls the read through the gRPC stub:

```python
return cast(tool_base_pb2.ExecuteCommandReply, self.stub.ExecuteCommand(
    self._fast(get_plates=fast_pb2.Command.GetPlates(**fields))))
```

and asserts `reply.response == SUCCESS`, `reply.return_reply`, plate ids `[3, 12]` (ascending), `plate_definitions` called once with `refresh=False`, `service.status` not called, health still `BUSY`, the lock still held and the Transfer thread alive; after release the Transfer finishes `SUCCESS` and health returns to `READY`. Further tests in the same class and in `TestGetPlatesRealCore` / `TestGetPlatesMapping` cover refresh, the unreachable path and `last_error`. The Python suite was not run from this repository (it needs galago-tools' own environment); the test source was read.

**Reply shape.**
- Success: `SUCCESS`, `return_reply=True`, `meta_data = {"plates": [{id, description, rowCount, colCount, workingCapacity}, ...]}`, sorted ascending by `id`; `id` is `int(p.id)`; an empty list is `SUCCESS` with `{"plates": []}`. No `kind` discriminator in the reply (unlike the other fast results that carry `result.to_dict()`).
- `refresh`: `optional bool refresh = 1`; the handler calls `service.plate_definitions(refresh=bool(params.refresh))`; `true` bypasses fast_mcp's knowledge cache, absent or false reads the cache.
- Failure mapping: instrument unreachable (`httpx.HTTPError`) gives `ERROR_FROM_TOOL` with `error_message` "instrument unreachable: <ExceptionName>: <text>"; an `InstrumentHTTPError` gives `ERROR_FROM_TOOL` with "instrument HTTP <status>: <body>". Neither carries a `plates` key (empty meta_data). No service object (tool not connected, `Configure` not run with simulated off) gives `NOT_READY` with "fast tool is not connected to an instrument: restart the tool server and Configure it with simulated off". Any other exception reaching the bypass wrapper gives `DRIVER_ERROR` with `str(e)` and no `plates` key.
- BUSY bypass: `READ_COMMANDS = frozenset({"get_plates"})` in `FastServer`; `ExecuteCommand` routes `field_name in READ_COMMANDS` straight to `_dispatchCommand`, skipping base_server's readiness gate and status bracket (never calls isReady, parseCommand or setStatus), so a BUSY tool stays BUSY. It never takes `_motion_lock` and never reads status (`GetPlates` is not in `MOTION_LOCK_COMMANDS`; an AST test forbids `_motion_lock` inside `GetPlates`). Estimate is `EST_READ_S = 1`.
- `last_error`: a thread-local `_read_bypass` flag makes the `last_error` setter drop writes made during a bypassed read, so a get_plates read (success or failure) never clears or overwrites the `GetStatus.error_message` while a Transfer runs. The one exception is the wrapper's own `DRIVER_ERROR` handler, which records the exception text.

**Differences from `.planning/research/FAST-GET-PLATES-CONTRACT.md` (the frozen commit wins; 07-06 follows it).**
1. Failure codes are now concrete: `ERROR_FROM_TOOL` for transport/HTTP failures (with the message prefixes above), `NOT_READY` when the tool has no instrument service, `DRIVER_ERROR` for an unexpected exception. The contract only said "a non-SUCCESS response code plus error_message". 07-06 must treat every non-SUCCESS code, or a SUCCESS reply without a `plates` array, as unavailable and never read `plates` from a failed reply. The tool-page error text for `NOT_READY` / `INVALID_ARGUMENTS` is hidden by galago-core, so do not depend on the message wording for UI decisions.
2. Added behavior not in the contract: the read never touches `last_error` (WR-04 parity with STACK), so the operator's error text mid-run is unaffected by plate refreshes.
3. Unchanged from the contract: proto shape (`optional bool refresh = 1`), meta_data keys and field names, ascending order, empty-list-is-success, no BUSY or motion-lock gate, `return_reply=True`. No `readFailed` kind or any other discriminator exists in this reply.
