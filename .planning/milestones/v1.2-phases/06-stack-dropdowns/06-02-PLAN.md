## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> tRPC tool.options (refresh: true) | an unauthenticated caller can request refreshes repeatedly |
| STACK tool server -> controller | reply size and structure are untrusted |
| controller -> audit log | client-controlled toolId and failure detail reach log rows |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04 | Denial of Service | refresh path / STACK manager reload | medium | mitigate | Refresh in-flight dedupe under its own key, REFRESH_MIN_INTERVAL_MS = 2000 reuse of the last successful refresh, 5 s deadline from 06-01; reads bypass the STACK BUSY gate so they cannot stall motion |
| T-06-05 | Denial of Service | parsers | medium | mitigate | MAX_LIST_ITEMS / MAX_TREE_NODES / MAX_NAME_LENGTH exported and boundary-tested; over-cap is unavailable too_large, never truncation; grpc 4 MiB receive limit backstops |
| T-06-06 | Repudiation / Tampering | failure and refresh logging | medium | mitigate | sanitizeLogText over the full details string, toolId bounded to 200 chars by the 06-01 input schema, one row per (tool, source, event) per 60 s |
| T-06-09 | Tampering | parsers reading Struct-decoded objects | medium | mitigate | Explicit named-property reads on plain objects only; a __proto__ / constructor key test proves no prototype change and no extra fields |
| T-06-SC | Tampering | npm/pip installs | high | mitigate | This plan installs no package; vitest, zod and grpc-js are already present |
</threat_model>
