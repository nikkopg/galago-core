<objective>
A run whose failed step the operator skipped must never look like plain success, and a run with a
FAILED step is never derived as completed (ERR-05 run level, D-18, D-19).

Purpose: today `getRunAttributes` gets one command instead of the run's array, so its status is always
"CREATED". The only "looks successful" surface is the full teal progress bar of a run whose failed
step was skipped (research section "Blast radius for D-18"). This plan adds a pure outcome helper,
fixes the call site and shows an orange "Skipped failure" badge and progress bar.

Output: pure `storedError.ts` and `runOutcome.ts` with unit tests, `utils.ts` delegating to it, and
`RunsComponent.tsx` wired. The permanent static-scan case for this wiring is added by 03-06 Task 3,
because 03-04 owns `staticScan.test.ts` in this wave.

Ordering: this is an F3 change, so it depends on 03-02 (D-10: the failing ERR-01 test is committed
before any F3 fix).
</objective>

## Deviations and resolved choices (recorded, not silent)

- **D-18 shape (research recommendation adopted):** `RunStatus` is NOT widened. The run-level outcome is a
  client-only union; the new member is named `COMPLETED_WITH_SKIPPED_FAILURE` (research A2) and labelled
  "Skipped failure" with the title "Completed, but a failed step was skipped, not completed."
  (UI-SPEC UA4).
- **Call-site fix (research Pitfall 6):** `RunsComponent` passes `run.Commands` and recomputes every
  poll. The status-compare memo guard is removed, because the function is synchronous and cheap.
- **FAILED takes precedence (D-19, narrower than research's "reproduce the order"):** a run with any
  FAILED row is FAILED even if its last row is COMPLETED. Today's order reports it COMPLETED. ERR-05
  forbids showing a tool error as success; the status string had no visible consumer before this phase,
  so nothing that rendered changes except the new badge.
- **Shared stored-error reader:** `storedErrorText` lives in its own module so 03-06's `stepErrorText`
  reuses it and the "has an error" rule cannot drift between the card and the run outcome.
- **Badge icon:** the optional `AlertTriangle` icon (UI-SPEC) is omitted to keep the row compact; text plus
  orange colour carries the signal.
