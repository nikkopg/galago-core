# Phase 5 — UI Design Contract

> Visual and interaction contract for the STACK command forms and reply display. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of UI change:** this phase adds NO new screens and NO new components from scratch. It
makes the existing generic tool-page machinery render for `ToolType.stack`:

- `controller/components/tools/constants.ts` — **data only**: the `commandFields.stack` entry
  (9 commands, every field born-empty, no `defaultValue`, no `select`). This single entry makes
  the tool-page command panel render for STACK and removes the "Invalid Tool Type" error alert
  from STACK tool pages.
- `controller/pages/tools/[id].tsx` — the command panel renders the STACK command list and
  born-empty forms; the `runCommand` reply's `meta_data` is captured and rendered read-only
  under the command form (GEN-03) through the shared bounded display.
- `controller/components/ui/BoundedRawJson.tsx` (or co-located equivalent) — `LatchRawJson` +
  `formatLatchRaw` extracted from `RunRecoverySection.tsx` into one shared bounded display
  (D-06: reuse or extract — never a second styled copy).
- `controller/components/tools/EditToolModal.tsx` / `EditToolConfig.tsx` / `ToolConfigEditor.tsx`
  — **zero code changes**: the existing generic config editor renders the STACK `host` / `port` /
  `transfer_timeout_s` / `ledger_dir` fields from the generated `Config.create({})` (D-05).
- `controller/components/tools/NewToolModal.tsx` — **zero code changes**: the tool-type list is
  derived from the generated `ToolType` enum, so "Stack" appears automatically after regen.
- `controller/components/tools/RunRecoverySection.tsx` — copy and behaviour unchanged; the latch
  read now sends `get_failure_latch` (the renamed `LATCH_READ_COMMAND`). D-08: do not restructure.

Everything below is locked either by upstream artifacts (source noted) or by this contract. The
executor implements from this file without re-deciding visuals.

## Born-Empty Display Contract (GEN-02 visual rule)

`commandFields.stack` carries no `defaultValue` anywhere (D-03, static-scan + `commandFields.test.ts`
pinned). The **display** must honour the same rule: today's shared `renderFields` fallbacks paint an
unchosen value into untouched fields — the number branch renders `Number(value || 0)` → "0", the
boolean branch renders `String(value || "false")` → "false", even though the stored form value is
the born-empty `""`.

**Contract: an untouched STACK field renders empty — no painted `0`, no painted `false`.** The
executor may satisfy this by (a) fixing the shared fallbacks in `renderFields` (untouched `""`
renders `""`; a real value renders as before), or (b) scoping the fix to STACK-sourced fields.
Option (a) also de-paints F.A.S.T. born number/boolean displays — a display-only change that aligns
F.A.S.T. with the same no-unchosen-value rule; `formValues` semantics and every payload are
unchanged either way (D-04's blank-handling is pinned by the D-07 wire test, not by rendering).

**No Switch for booleans.** A Switch is always in one of two states — it cannot render born-empty,
so it would paint an unchosen physical decision. The existing `Input type="boolean"` text field
(quirky but honest) stays; the operator types `true`/`false` as text and the D-07 blank-optional
wire case pins what a blank sends.

## Interaction Contract (UI-08 hard rules — non-negotiable, scan-enforced)

These are project constraints (PROJECT.md + `test/staticScan.test.ts`) rather than checker
dimensions, but the executor binds to them here:

1. **No timers/polling anywhere in this UI.** The `meta_data` panel is captured from the already-
   resolved `runCommand` promise (state set in `onSuccess`) — never a query, never
   `refetchInterval`, no new timers in any touched module. The Run Recovery card stays in the
   no-timers scan list unchanged.
2. **No Enter-bound default.** The command panel additions add no `<form>` wrapper, no
   `onKeyDown`, no `autoFocus`, no `defaultValue`/`defaultChecked`, no `type="submit"`. "Send
   Command" fires on click only; pressing Enter while typing a field does nothing.
3. **Nothing pre-selected.** The command Select is born on its placeholder (no option chosen);
   every field is born empty (Born-Empty Display Contract); the ack radios/guid remain per Phase 4.
4. **No instrument-state gating.** "Send Command" stays enabled regardless of run state — the page
   gains no run-state checks; the server refuses operator-only commands (OPR-04/OPR-05) and its
   refusal text surfaces through the error toast. The "gray the recovery card while a STACK step
   runs" idea is DEFERRED (05-CONTEXT) — do not build it.
5. **Single send path, once, never retried.** One `runCommand` mutation per click through the
   existing `executeCommandWithToast`; toasts settle but never resend; no retry affordance in copy.
6. **Read-only reply display.** The `meta_data` panel is display-only: no editing, no table, no
   send path, no hooks feeding any mutation — it contains nothing that can trip the single-send-
   path scans (same property D-06 relies on for `LatchRawJson`).
7. **At most one reply panel.** The panel shows the most recent completed send's `meta_data`;
   each new send replaces it. No list of replies accumulates.
8. **OPR-05 invariants stay green.** `acknowledge_failure` never appears in the command dropdown
   (absent from `commandFields.stack`; the flipped scan keeps the ack-absence assertions); the
   latch read keeps exactly one reader (`LATCH_READ_COMMAND` → `"get_failure_latch"`); `/latch/i`
   stays out of the send-path copy modules.
