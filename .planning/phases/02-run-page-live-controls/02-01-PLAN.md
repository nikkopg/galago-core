<objective>
Deliver the run-page control bar and the one shared, confirmed send path for live instrument control.
An operator watching a running F.A.S.T. step sees its state and percent, clicks Pause/Resume/Abort,
confirms in a modal whose yes/no decisions start empty, and the action reaches the running tool
through `commandQueue.toolControl`. Refusals are shown verbatim in a persistent toast. Nothing is
optimistic: the bar changes only on the next poll.

Purpose: UI-01, UI-02, UI-03 and the client half of UI-08. Implements D-01..D-09 (D-06 is rated
costly: every later control entry point routes through RunControlConfirmModal). This plan fixes the
interfaces that plans 02-02, 02-03 and 02-05 consume: `controlDecision.ts`, `hooks/useRunControl.ts`
and the `RunControlConfirmModal` props.

Output: `controlDecision.ts`, `hooks/useRunControl.ts`, `RunControlConfirmModal.tsx`, `ControlBar.tsx`,
the `persistentErrorToast` helper, the bar mounted in `RunsComponent`, the `command` field on the
running `RunStateEnvelope`, and `test/controlDecision.test.ts`.
</objective>
