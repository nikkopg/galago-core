- RESEARCH A9 / OQ 5: the 1500 ms tolerance equals one lane-loop delay (command_queue.ts line 180); the
  primary loop may claim the estimate up to one poll before the fast worker claims the F.A.S.T. step.
- A real-mode get_transfer_estimate is short (one manager request); its window may be well under a second.
  Containment, not duration, is the test.
- Per-key one-shot is claimed only for explicit keys (D-08); the estimate writes no ledger record.
- The third plate's labware profile must match the event-2 protocol's labware_profile parameter (default
  Default); the operator confirms it physically.
- Under the amended D-02 the third plate already sits on nest-3 from before event 1 (09-03 precondition 3),
  and event 1 does not move it. The readiness step is therefore a check, not a staging move. nest-1 holds
  plate 1 until in1 runs, so "nest-1 empty" is not a readiness condition.
- GetLabwarePresence takes only a robot name (stack.proto), so it reads whether the arm's gripper holds
  labware, not which nest is occupied. Nest occupancy is the operator's by-eye confirmation.
- Reply files are split on purpose: this plan saves the operator's readiness reply as *-e2-readiness.txt;
  09-11 Task 1 saves its own reply (with the fresh nest-3 / nest-1 round trip) as *-e2-go-readiness.txt. The
  round trip is not run here, so the post-e2-readiness baseline must show no new Transfer.
- The galago-tools tools/ status shows one line, the untracked tools/fast-mcp-locks/ runtime directory; that
  is accepted, any other line is not.
</flagged_assumptions>
