# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mode: `--auto`. No questions were asked. Every open choice took the recommended option and is listed under "Auto Decisions" at the end.
> Scope: one shared `OptionsSelect` control (modes `loading`, `ok`, `unavailable`, `variable-bound`), a per-source Refresh button with a status line, the "ambiguous" and "(not reported by instrument)" flags, and the variable-bound child hint. It is used in three hosts: `controller/pages/tools/[id].tsx`, `controller/components/protocols/AddToolCommandModal.tsx` and `controller/components/protocols/CommandDetailsDrawer.tsx` (edit mode only). Option-label context (robot state, `hasLid`, nest type) is deferred and out of scope.

## Layout and Interaction Contract

### Field layout (all three hosts use the same structure)

```
[label]                                        <- host's existing label (tool page: FormLabel with field.name)
[ OptionsSelect  flex=1 ] [ No Variable 180px ]  <- the variable Select exists only in the modal and drawer
[ ↻ Refresh ]  from instrument · 12 items · fetched 14:02:11   <- Refresh row, only under the FIRST field that uses the source
hint line (only in `unavailable` and cascade-child-bound states)
```

- The control replaces only the left `Input` of the existing row. The 180px "No Variable" `Select` and `handleVariableSelect` stay exactly as they are (D-13). The tool page has no variable `Select`.
- The Refresh row is one per source per form, never one per field (D-12). It sits under the first field in form order that uses the source:
  - `stack.robots`: under `robot`
  - `stack.labwareProfiles`: under `labware_profile`
  - `stack.devices`: under `source_device` (one Refresh serves source and destination)
  - `stack.transferProfiles`: under `source_transfer_profile`
  - On `get_labware_presence` the only bound field is `robot`, so the only Refresh is the `stack.robots` one.
- Refresh row: `HStack spacing={2} mt={1}`, button left, status line right of it, status line 12px muted. It does not wrap under 480px; the status line wraps below the button if needed.
- Field order and labels are unchanged (the form order in `commandFields.stack`: `robot`, `labware_profile`, `source_device`, `source_deck`, `source_nest`, `source_transfer_profile`, `destination_device`, ..., `destination_transfer_profile`). The cascade is not visually nested or indented.

### `OptionsSelect` modes

| Mode | When | Render |
|------|------|--------|
| (no control) | Drawer while not `isEditing` (the run page embeds it read-only) | The drawer's existing disabled `Input`, unchanged, and no Refresh row. Zero reads. |
| `loading` | First load in flight (`isInitialLoading`, not `isLoading`) | Disabled `Select`. First option reads "Loading…". If the saved value is non-blank, it is shown as the only other option and selected, with no flag. No Refresh row yet. The form and the Save/Run buttons stay usable. |
| `ok` | Server returned `status: "ok"` and the query is not in error | Enabled native `Select`. The first child is an explicit `<option value="">` with an empty label. Then the offered options, in the order delivered. Nothing is `selected` or `defaultValue`d except the operator's or hydrated value; never `options[0]`, even when only one option exists. If the saved value is non-blank and not offered, one extra `<option>` is appended: `{value} (not reported by instrument)`, and it is selected. Refresh row shown. |
| `unavailable` | Server returned `status: "unavailable"` or the query is in error (ignore any previous `data`) | The host's plain text `Input`, with the current value kept. Hint under it: "Instrument list unavailable — type the value". The Refresh button stays so the operator can retry; the status line is replaced by the hint. |
| `variable-bound` | The field value is a `{{variable}}` reference (modal and drawer only) | `Select` disabled, with a single selected option showing the variable reference, for example `{{plate_count}}`. The variable `Select` on the right shows the chosen variable. No flag, no warning. |

### Cascade (device, deck, nest; source and destination)

- Source and destination are independent cascades. Both are built from the one `stack.devices` read.
- Option label is the plain name. The stored value is the plain name only, never `unifiedName`. Duplicates are never collapsed, so two identical names appear as two identical lines (React keys include the index).
- A device with no calibrated deck is still offered. Its deck `Select` then has only the blank option and shows the note: "No calibrated decks on this device". Same for nests: "No calibrated nests on this deck". These are valid `ok` answers, not `unavailable`.
- A child `Select` whose parent is blank and whose own value is blank is disabled, with no options. It has no extra text.
- A child whose value is non-blank is never disabled and never cleared by a list change. A non-blank value that is not offered (including an uncalibrated deck or nest) shows as `{value} (not reported by instrument)`.
- Operator change of a device clears the same side's deck and nest to `""`. Change of a deck clears the nest to `""`. A cleared field goes back to blank, never to the first child. These are written in the same state update as the parent (one `setFormValues` or one `setCommandParams` call). Refresh and first load never clear anything.
- When a parent is bound to a `{{variable}}`: its children render as a typed `Input` (not disabled) with the hint "child list unavailable while the parent is a variable". If a child is itself bound to a variable, `variable-bound` takes precedence for that child.

### Flag rendering

| Flag | Where | Text | Colour |
|------|-------|------|--------|
| Ambiguous | Option label in the `ok` list | `{name} (ambiguous — adapter will refuse)` | Native `<option>` cannot be reliably styled, so the flag is plain text inside the label, not an icon or colour alone. Where the browser honours it, set `color` to the Warning colour on that `<option>`. |
| Not reported | The extra option for a saved, non-offered, non-blank value | `{value} (not reported by instrument)` | Muted, where the browser honours it |

- Ambiguous options stay selectable. A device-level ambiguity flags every deck and nest under it. A deck-level ambiguity flags every nest under it (Open Question 1, recommended option taken). A nest repeated under different decks is not ambiguous and is not flagged.
- Blank values (`""`, `undefined`) never show a "not reported" warning. The warning is shown only when the list loaded successfully (not in `loading` or `unavailable`).
- Values are compared with `String(a) === String(b)`; never trimmed, lower-cased or normalised.

### Refresh

- Button label "Refresh", `RepeatIcon` on the left, `aria-label="Refresh {source} list"` where `{source}` is one of "robots", "devices", "labware profiles", "transfer profiles".
- Idle: enabled. In flight: `isLoading`, text "Refreshing…", button disabled. The current list stays rendered and the selects stay usable. Never clears a selection.
- Success: the list and the status line update.
- Failure: the field switches to `unavailable` mode (text input keeps the value, hint appears). The previous list is not shown.
- Not rendered when the host passes `enabled: false`.

### Status line

- Format: `from instrument · {N} items · fetched {hh:mm:ss}` (24-hour, local time, from the server's `fetchedAt`, so a cached list shows its original read time). One item reads `1 item`, zero reads `0 items`.
- `N` is the number of top-level entries in that source (devices, robots, labware profiles, transfer profiles), after the server dropped invalid entries.
- If the server marked the list degraded (dropped empty or `{{x}}`-style names), append ` · some entries skipped`.
- Not shown in `loading` or `unavailable` mode.
- `aria-live="polite"` so a screen reader hears the update after Refresh.

### Accessibility

- Every control keeps its host label. The hint and status line are linked with `aria-describedby` to the control.
- The Refresh button is a real `<button>` with a visible text label, reachable by Tab right after its field.
- The ambiguity and not-reported flags are text, never colour or icon alone.
- The `loading` select has `aria-busy="true"`.

### What does not change

- `commandFields.stack` is not edited; `step_key` and `timeout_s` stay typed inputs.
- `list_*` and `get_*` tool-page commands keep their v1.1 forms (the boolean `refresh` checkbox on `list_*` stays as it is).
- The values sent are the plain strings the operator would have typed (DRP-09). No submit path changes.

## UI Considerations

Applicable state considerations resolved: 9 covered, 2 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Option lists (robots, devices, labware profiles, transfer profiles) | ✅ covered | A validated empty array renders the `ok` mode with only the blank option and the status line "0 items"; it is not treated as unavailable. Copy is in the Copywriting Contract. |
| empty | Deck and nest lists after the calibration filter | ✅ covered | The child `Select` has only the blank option and the notes "No calibrated decks on this device" and "No calibrated nests on this deck". |
| loading | First read of each source | ✅ covered | `loading` mode: disabled select with "Loading…"; a saved value shows without a flag; the form stays usable. |
| error | Failed, timed-out, refused or malformed read | ✅ covered | `unavailable` mode: text input with the hint "Instrument list unavailable — type the value". Never a stale list (check `isError` first). |
| partial | Degraded list (empty or `{{x}}` names dropped) | ✅ covered | Status line appends "some entries skipped"; the remaining entries are offered. |
| zero-one-many | A list with exactly one option | ✅ covered | Nothing is preselected; the blank option stays selected until the operator chooses. |
| long-text | Long device, deck, nest or profile names, and long flag suffixes | 🧪 backstop | Native `<option>` text is clipped by the control width. Held-out visual check with a 60-character name plus the ambiguous suffix, in the modal (narrowest host). |
| duplicate | Two options with the same name | ✅ covered | Both shown with the same label and index-based React keys; both flagged when ambiguous (D-08). |
| stale | Saved value not in the loaded list; uncalibrated saved deck or nest | ✅ covered | Kept and selected, shown as "(not reported by instrument)"; blank values never warn. |
| overflow | A list of up to the server cap (about 10k items) | 🧪 backstop | Native `Select` handles it but is slow to scroll; the server cap bounds it. Held-out check with a large fixture. Searchable dropdown is out of scope (D-11 locks native `Select`). |
| interaction | Refresh pressed while a selection exists | ✅ covered | The selection is never cleared; children are unchanged (the D-09 test). |
| live-only | Dropdowns against a simulated STACK | ⚠ unresolved | A simulated STACK answers SUCCESS with no `meta_data`, so every field shows `unavailable` (typed input). Real-list visuals need a real or PAC-simulated STACK; the planner treats it as one live-only UAT item (RESEARCH finding 5). |
