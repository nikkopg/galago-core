> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

| 3xl | 64px | not used by this phase |

Exceptions (all taken from the approved mockup or the CONTEXT D-11 well-size rule; none are free choices):

## Layout and Interaction Contract

### Form order (transfer)

Order is the existing `commandFields.fast.transfer` order, which is unchanged: `source_deck`, `dest_deck`, `source_plate_id`, `dest_plate_id`, then the six well fields, `volume`, `tip_reuse`. The picker takes the place of the six well fields:

```
source_deck        [ Select 1-6 ] [No Variable 180px]
dest_deck          [ Select 1-6 ] [No Variable 180px]
source_plate_id    [ Select plates ] [No Variable 180px]
[ ↻ Refresh ]  from instrument · 7 items · fetched 14:02:11      <- once, under source_plate_id
dest_plate_id      [ Select plates ] [No Variable 180px]
+-- WellPicker panel (inline, never a modal) ------------------------------+
|  Source plate                    Destination plate                        |
|  12 · Greiner 96 flat ·          7 · Corning 96 round ·                   |
|  drag to select                  click to place                           |
|  [ grid ]                        [ grid ]                                 |
|  status line                                                              |
|  [▸ Edit as fields]  [Clear selection]                                    |
|  (Collapse: the six typed fields)                                         |
+---------------------------------------------------------------------------+
volume             (unchanged)
tip_reuse          [x] Reuse tips
```

- The 180px "No Variable" `Select` and `handleVariableSelect` stay exactly as they are in the modal and drawer (Phase 6 D-13). The tool page has no variable `Select`.
- The picker is rendered once, at the position of the first well field (`source_start_row`), and the other five well fields are skipped in the host's field loop. Hosts render the six typed fields (so number, text and variable-picker behaviour is inherited) and pass them into the picker's Collapse as children.
- The picker is never a modal and never leaves the form flow. The Refresh row is one per source (Phase 6 D-12): the `fast.plates` Refresh sits under `source_plate_id` and serves both plate fields.

### Plate dropdown (`source_plate_id`, `dest_plate_id`)

Reuses `OptionsSelect` modes from Phase 6 unchanged (`loading`, `ok`, `unavailable`, `variable-bound`), with these plate-specific rules.

| Aspect | Contract |
|--------|----------|
| Option label | `{id} · {description}`, for example `12 · Greiner 96 flat` (copied from the mockup). Empty description: the label is the id only. Never truncated; a native `<option>` clips naturally. |
| Option value | The numeric id. The control writes a **number** to params (`""` for blank). Compared with `String(a) === String(b)`, never trimmed or normalised. |
| First option | An explicit `<option value="">` with an empty label. Nothing is preselected, even when the list has exactly one plate. |
| Order | The reply's order. Not sorted. |
| Duplicate id | Every entry sharing an id reads `{id} · {description} (duplicate id — check instrument)`. Stays selectable. Warning colour where the browser honours it. |
| Saved id not offered | One extra option, selected: `{value} (not reported by instrument)`. Not shown while loading or unavailable. |
| `loading` | Disabled `Select`, first option "Loading…", saved value shown unflagged (Phase 6). |
| `unavailable` | The plain **numeric** `Input` (`inputMode="numeric"`, non-digit characters are ignored, the saved value is kept) and the hint "Instrument list unavailable — type the value". Refresh stays. A stale list is never shown. |
| `variable-bound` | Disabled `Select` showing the `{{variable}}` reference. Phase 6 behaviour, unchanged. |
| Empty list | `ok` mode with only the blank option and the status line "0 items" (Phase 6 rule). Not `unavailable`. |

Refresh and status line follow Phase 6 exactly, with source label "plates": button `aria-label="Refresh plates list"`, status line `from instrument · {N} items · fetched {hh:mm:ss}`, degraded append ` · some entries skipped`, `aria-live="polite"`.

### Deck dropdown (`source_deck`, `dest_deck`)

| Aspect | Contract |
|--------|----------|
| Control | Native `Select` through the shared select view (no read, no hook, no Refresh row, no status line). |
| Options | A blank `<option value="">`, then `1`, `2`, `3`, `4`, `5`, `6` (value and label both the digit), taken from the one `DECK_SLOTS` constant (D-08). |
| Born empty | Nothing selected until the operator chooses. Never `defaultValue`, never `options[0]`. |
| Writes | A number. Blank writes `""`. |
| Saved value outside 1-6 or non-numeric | Kept verbatim as one extra selected option: `{value} (not a deck slot 1-6)`. Blank values show no flag. |
| `variable-bound` | Disabled `Select` showing the `{{variable}}` reference (modal and drawer). |
| Offline | Unaffected. Decks do not depend on the instrument, so they never fall back to a typed input. |

### "Reuse tips" checkbox (`tip_reuse`)

```
tip_reuse                                    <- the host's existing field label stays above
[x] Reuse tips                               <- Chakra Checkbox, label 16px / 400
Checked sends reuse, unchecked sends fresh.  <- 12px muted helper
```

| Saved value | Checkbox | Extra text |
|-------------|----------|------------|
| `"reuse"` | checked | none |
| `"fresh"` | unchecked | none |
| blank | indeterminate | 14px warning: `(saved value is blank — not reuse/fresh)` |
| any other string `{v}` | indeterminate | 14px warning: `(saved value '{v}' — not reuse/fresh)` |
| `{{variable}}` | disabled, indeterminate | the variable reference in 14px muted text, in place of the flag |

- A **new** step starts checked (`tip_reuse: "reuse"` is written when the form initialises a new step, so what is shown and what is sent are always the same). This is the one allowed default on a Transfer field (PLT-07, user decision 2026-11-06).
- Opening a saved step never writes a value. The saved value stays verbatim until the operator clicks. A click then writes `reuse` (to checked) or `fresh` (to unchecked). From the indeterminate state a click goes to checked, then toggles between checked and unchecked.
- The checkbox is not wrapped in the 180px variable `Select` row in a way that changes how the host lets an operator bind a variable: in the modal and drawer the "No Variable" `Select` stays to the right of the checkbox row, as for every other field.
- Accent: `colorScheme="teal"` so checked and indeterminate fills use the project accent (the Chakra default would be blue).

### WellPicker (PLT-08, PLT-09)

#### Anatomy

- Container: `Box` panel, `bg` secondary (see Color), `borderRadius="xl"`, `p={4}`, full width of the form column.
- Grids row: `Flex wrap="wrap" gap={6}`. Source column then destination column. Side by side when both fit, otherwise stacked, from one layout. Each column has `minW={0}` and `maxW="100%"`.
- Each grid column, top to bottom:
  1. Title, 14px / 700: "Source plate" or "Destination plate".
  2. Caption, 12px muted, `mb={1}`: `{plate label} · drag to select` (source) or `{plate label} · click to place` (destination), for example `12 · Greiner 96 flat · drag to select`. The plate label is the same `{id} · {description}` used in the dropdown (id only when the description is empty).
  3. The grid box: `overflowX="auto"`, `maxW="100%"`. The grid scrolls horizontally inside its own box and never widens the form (the G-03-3 lesson). The hit-test box is the **inner** grid element, so scrolling needs no extra code.
  4. Under the destination grid only, when the plates differ in size, the mismatch warning (below).
- Below the grids row, `mt={4}`: the status line. Below it, `mt={2}`: the action row (`HStack spacing={2}`): "Edit as fields" toggle on the left, "Clear selection" on the right. Below that, the Collapse with the six typed fields.
- The action row sits above the Collapse (the mockup put "Clear selection" below the fields, but the fields are collapsed by default, so the button would be hidden with them).

#### Grid

- CSS grid: `grid-template-columns: {gutter}px repeat({cols}, {well}px); gap: 3px;` (mockup: `14px repeat(12, 18px)`). First row is the column header (column numbers, 1-based). Each following row starts with a row label.
- Row labels: `A`..`Z`, then `AA`, `AB` and so on. Column labels are 1-based. Axis labels are 11px muted and centred. When the cell is narrower than 14px, label every second column (1, 3, 5, ...) so labels do not collide.
- `user-select: none; touch-action: none`. Wells and axis labels are `aria-hidden`.
- Hit-testing is arithmetic from the inner grid's `getBoundingClientRect()` and the fixed cell stride (not `elementFromPoint`).

#### Well size

| Plate columns | Well diameter |
|---------------|---------------|
| 1 to 12 | 18px |
| 13 to 48 | `max(8, round(18 - (cols - 12) / 2))` px, so 24 columns is 12px and 48 columns is 8px (floor) |

At 12px wells, a 384-well plate is about 377px wide, so two fit side by side in the 900px modal (about 852px usable) and stack in the narrower drawer, each scrolling inside its own box if needed. Planner: confirm by eye in UAT; widen the modal for this command only if two 384 grids do not fit.

#### Interaction

| Gesture | Source grid | Destination grid |
|---------|-------------|------------------|
| Pointer down (primary button only) | Starts a drag at that cell; selects the 1x1 block; writes the four source fields | Nothing |
| Pointer move while dragging | Rectangle between the anchor cell and the current cell, normalised so any drag direction works; writes `source_start_row`, `source_start_col`, `num_rows`, `num_cols` live | With a source block present, shows the dashed same-size footprint with its top-left under the pointer cell. Without a source block, nothing |
| Pointer leaves the grid | The drag continues (pointer capture); the cell clamps to the nearest edge cell | The hover footprint is removed |
| Pointer up, pointer cancel, lost capture | Ends the drag | n/a |
| Click | n/a | Places the footprint and writes only `dest_start_row` and `dest_start_col`. Accepted only where the footprint fits. A click where it does not fit does nothing and writes nothing |

- Source drag sets all four source fields at once. A new source drag keeps any destination placement and re-checks whether it still fits (D-13).
- Writes use uppercase row letters and 1-based column numbers. Typed row letters are matched case-insensitively for display only; a typed value is never rewritten.
- Hover footprint on the destination is UI-only state and is never written to params.
- Changing a plate never clears or rewrites the six well fields (D-13). Fit is re-checked at render time and a block that no longer fits is drawn in the `bad` state on its in-bounds wells and flagged, never clipped.
- Typed edits redraw a grid only when every field that side needs parses. Otherwise that grid shows nothing selected and the typed values stay as entered.
- Keyboard: the grids have no keyboard navigation (PLT-08). Keyboard use goes through the typed fields, reached with the "Edit as fields" toggle.
- Pointer feedback: `cursor: crosshair` on wells. On a destination grid that is showing a size mismatch the cursor is `not-allowed` and clicks do nothing.

#### Status line

12px, `aria-live="polite"`, `min-height: 16px` so the layout does not jump. The first row that applies wins.

| # | Condition | Copy | Colour |
|---|-----------|------|--------|
| 1 | The source block parses but does not fit the source plate | `Source block does not fit the source plate` | Danger |
| 2 | The block does not fit the destination plate at the hovered or placed position | `Block does not fit the destination plate here` (mockup copy) | Danger |
| 3 | A saved value cannot be shown on the grid (see "Flagged values") | `Some saved values can't be shown on the grid — see Edit as fields` | Danger |
| 4 | Either grid is hidden | `A plate grid is unavailable — use the fields below` | Muted |
| 5 | No source block | `Nothing selected. Fields start empty.` (mockup copy) | Muted |
| 6 | Source block, no destination | `{N} wells selected. Now place them on the destination.` (mockup copy; `1 well selected.` when N is 1) | Muted |
| 7 | Source block and destination placed | `Transfer {N} wells: {A1} → {B3}` (mockup copy, with the `→` arrow; `Transfer 1 well: ...` when N is 1) | Muted |

`{N}` is `num_rows × num_cols`. `{A1}` and `{B3}` are the row letter plus column number of the source start and the destination start.

#### Size mismatch (D-15, PLT-09)

When both plates are known with usable geometry and their `(rowCount, colCount)` pairs differ (compared as a pair: 8×12 vs 12×8 is a mismatch even though both have 96 wells), the destination grid shows no footprint and ignores clicks, and the warning is shown under it:

`Plates differ in size (8×12 vs 16×24) — the F.A.S.T. refuses cross-format transfers (-9006)`

- 14px, warning colour, `WarningTwoIcon` (`aria-hidden`) before the text, wrapping inside the grid column. It is text, not colour alone.
- The caption for the destination in this state is the plate label only (the words "click to place" would be misleading).
- The typed destination fields stay editable. Saving is not blocked. The tool server stays the final check.
- The warning applies only when both plates are known. With an unknown plate or unknown geometry the grid is hidden instead.

#### Hidden grid (no grid for that plate)

The grid is replaced by a placeholder box of the same column width (min 240px): `borderWidth="1px"`, `borderStyle="dashed"`, `borderRadius="md"`, `p={4}`, 14px muted centred text. The title stays. The caption is dropped.

| Cause | Placeholder copy (`{side}` is "source" or "destination") | Forces "Edit as fields" open |
|-------|-----------------------------------------------------------|------------------------------|
| No plate chosen | `Choose a {side} plate to show its grid` | yes |
| Plate list `unavailable` | `Plate list unavailable — type the wells below` | yes |
| Plate id not reported by the instrument | `Plate {id} is not reported by the instrument — type the wells below` | yes |
| Plate has no usable `rowCount` / `colCount` | `Plate {id} has no usable size — type the wells below` | yes |
| Duplicate id whose entries disagree on size | `Plate {id} is listed twice with different sizes — type the wells below` | yes |
| Plate bound to a `{{variable}}` | `The {side} plate is set by a variable — type the wells below` | yes |
| Plate list still `loading` | `Loading plates…` | no (avoids a flicker for a read that lasts a moment; Auto Decision 6) |

When only one grid is hidden the other still works: a plate-known source grid can still be dragged and writes the four source fields.

#### "Edit as fields"

- Toggle: `Button` `variant="link"` `size="sm"`, `colorScheme="teal"`, label `Edit as fields`, `ChevronRightIcon` when closed and `ChevronDownIcon` when open, `aria-expanded`, `aria-controls` the Collapse.
- Closed by default. Opens and closes on click while not forced.
- **Forced open, and cannot be closed,** while any of these holds: either grid is hidden (table above, except `loading`); any of the six fields holds a `{{variable}}`; any of the six fields holds a flagged value. While forced, the toggle is `aria-disabled="true"` (not removed), the chevron stays down, and a 12px muted note follows it: `Kept open: a plate grid is unavailable`, `Kept open: a field holds a variable`, or `Kept open: a value needs attention` (first match in that order).
- The tool page has no variables, so there the variable cause never applies.
- Content, in the mockup's order: `source_start_row`, `source_start_col`, `num_rows`, `num_cols`, `dest_start_row`, `dest_start_col`. Each is born empty: a blank `""` shows an empty input, never `0` (the modal's default `number` rendering must not be inherited). Typed edits sync to the grids.
  - Tool page: `SimpleGrid minChildWidth="120px" spacing={2}`, the mockup's auto-fit grid.
  - Modal and drawer: one field per row in the host's own row layout (`[Input flex=1][No Variable 180px]`, `VStack spacing={4}`), because the 180px variable `Select` does not fit a multi-column grid.
- A `{{variable}}` in a field shows as the field's value with the variable `Select` set, and that side's grid shows nothing selected for it.

#### Flagged values

A value is **blank** when it is `undefined`, `null`, `""` or the legacy `0` (older steps and untouched modal number fields hold `0`). Blank is never flagged and never forces the section open. A value is **flagged** when it is non-blank and unusable. A flag is 14px warning text under the field inside the Collapse, and the value is kept exactly as saved.

| Condition | Flag text |
|-----------|-----------|
| Row is not 1-2 letters | `Row '{v}' is not a 1-2 letter row — kept as saved` |
| Row is past the last row of the plate | `Row '{v}' is past the last row ({last}) — kept as saved` |
| Column is not a whole number of 1 or more | `Column '{v}' is not a whole number from 1 — kept as saved` |
| Column is past the last column | `Column {v} is past the last column ({cols}) — kept as saved` |
| `num_rows` or `num_cols` is not a whole number of 1 or more | `{field} must be a whole number from 1 — kept as saved` |

Row and column "past the last" checks need a known plate; with no usable geometry the grid is hidden and the typed values simply stand.

#### Clear selection

- Label `Clear selection`, `Button` `size="sm"` `variant="outline"` (neutral, not a destructive colour).
- The only action that empties the six fields. It sets all six to `""` (never `0`), which clears both grids and the status line returns to "Nothing selected. Fields start empty."
- Disabled when all six fields are already blank. No confirmation dialog: it clears only unsaved form state, the plate and deck selects are untouched, and the operator can re-drag (Auto Decision 8).

### What does not change

- `commandFields.fast` is not edited. The binding map decides how fields render.
- The wire shape is unchanged. Plate and deck values are numbers, `tip_reuse` is the string `reuse` or `fresh`, and well rows are uppercase letters.
- An unset plate or deck is saved as `""`, never `0` (D-07). Every other field keeps today's fill-in.
- The read-only drawer on the run page shows its existing disabled inputs, no grid, no Refresh, and sends no read.
- `get_plates` is never a step or a tool-page command.
- Phase 6 stack forms are untouched.

### Accessibility

- Every control keeps its host label (`source_plate_id`, `source_deck`, `tip_reuse`, and so on). Hints, flags and the Refresh status are linked to their control with `aria-describedby`.
- The grids are pointer-only by design (PLT-08). They are `role="group"` with `aria-label="Source plate grid"` / `"Destination plate grid"` and `aria-describedby` pointing at the status line. The typed fields are the full keyboard and assistive-technology path, so the "Edit as fields" toggle is a real `<button>` reachable by Tab.
- The status line is `aria-live="polite"`. Every flag, warning and mismatch is text (with an icon only as decoration), never colour alone.
- The `loading` plate select keeps `aria-busy="true"` (Phase 6). Pointer capture is released on pointer-up, cancel and lost-capture so a drag never gets stuck.
