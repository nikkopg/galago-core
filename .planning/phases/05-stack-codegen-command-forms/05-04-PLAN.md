<objective>
Close the one Phase-5 verification gap (CR-01 Critical + WR-01 Warning): the tool page's real
value pipeline corrupts boolean and cleared-number STACK command fields before the blank strip
and encoder ever see them.

- CR-01: a STACK boolean field (e.g. list_devices.refresh) is rendered as `<Input type="boolean">`
  (an invalid HTML input type that falls back to a text input). handleInputChange stores the typed
  STRING; omitBlankParams keeps the non-empty string; the generated encoder's protobufjs
  `Writer.bool` is `value ? 1 : 0`, so a typed `"false"` encodes as `1` → decodes `true`. There is
  currently NO input that sends `false`. This violates verification truth 9 and CONTEXT D-04
  ("the payload sends what the operator typed").
- WR-01: a typed-then-cleared Chakra NumberInput stores `NaN` (parse("") === NaN). isBlank(NaN) is
  false, so omitBlankParams keeps it and a visually-emptied timeout_s is sent as NaN.

Fix (per the verification gap's own `missing:` criteria and the user's decision on 2026-11-02):
COERCE in the value pipeline, do NOT swap the control. The `<Input type="boolean">` text field
stays verbatim (05-UI-SPEC AC-4 is locked: "the existing Input type=boolean text field (quirky but
honest) stays"; "No Switch for booleans"). A pure coercion step converts boolean-typed string
values to real booleans before the STACK strip, and the cleared-number path stores the born-empty
"" instead of NaN (with isBlank also treating NaN as blank for defence in depth).

Purpose: make a STACK send carry exactly what the operator chose — a real `false`, and nothing at
all for a field they emptied — proven on the real generated encoder through the page-shaped params
the page actually produces (the blind spot the fixture-only D-04 wire pin slipped through).
Output: coercion in commandParams.ts + [id].tsx, three test files updated, full phase gate green.
</objective>
