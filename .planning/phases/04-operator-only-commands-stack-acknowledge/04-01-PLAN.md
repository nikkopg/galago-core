<objective>
Implement the server half of the operator acknowledge: a new zero-import spec module
`server/recoveryActions.ts` (D-05, D-08, D-10, D-13-adjacent data) and the rerouted audited
`recoveryControl` path (D-06, D-09), so that a completed recovery request goes through
`tool.recoveryControl` to exactly one `tool.controlCommand(action, params)` call whose payload the
FakeGrpc proves is `{ stack: { acknowledge_failure: { guid, arm_inspected: "yes" } } }` — fail-closed,
fixed refusal order, audited at every outcome, never retried (OPR-01 server side, OPR-02).

Purpose: `runControl` stays `{ fast }` (locked; ACK-AND-F3.md §1.2 — adding `stack` there would start
the run-state poller, create dead Pause/Resume/Abort buttons, and open a second valid ack path through
`toolControl`). The recovery-only spec is the only mechanism, and it must be the same module the client
imports so validator behaviour cannot drift between card and server.

Output: `server/recoveryActions.ts`, rerouted `server/recoveryControl.ts`,
`test/recoveryActions.test.ts`, extended `test/recoveryControl.test.ts`.

Task 1 is this plan's tracer: the thinnest end-to-end path — completed request via the tRPC caller
(the client layer is plan 03) → `recoveryControl()` → `tool.controlCommand` → FakeGrpc, exact payload
asserted once. Task 2 expands it with the fail-closed refusal matrix, refusal ordering, strict-success
and transport-error audit cases.
</objective>
