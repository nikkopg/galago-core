<objective>
Build the operator's acknowledge surface on the proof plan 04-01 laid: the Run Recovery card gains the
guid entry and the "Acknowledge failure…" button, the shared `RunControlConfirmModal` restates the guid
verbatim and gates Confirm on an explicit born-empty "yes", and `createConfirmedSender`'s recovery
branch is rebuilt on the recovery spec (`listRecoveryActions`/`getRecoverySpec`) instead of the
hard-coded `RECOVERY_UI_ACTIONS` (OPR-01 client half; D-05 mirror, D-07, D-08, D-09).

Purpose: the client check must literally be the server's check (one zero-import
`isValidRecoveryGuid` imported by the card), the confirmation must never be defaulted, auto-submitted
or retried by the UI, and every static invariant this repo enforces for control UIs (UI-08, single send
path, no Enter-bound default) must hold on the new code from the first commit.

Output: rerouted `controlDecision.ts`, extended `RunControlConfirmModal.tsx`, extended
`RunRecoverySection.tsx`, widened `hooks/useRunControl.ts`, extended `test/controlDecision.test.ts`.

Task 1 is Carl's decision-state sliver: pure logic — spec-driven completion, copy maps, request
carrying params — verified by pure tests. Task 2 is the render surface: modal per-kind render and the
card's guid entry + wiring.
</objective>
