<objective>
Make a failed tool step reach the operator with the tool's own words and the real code name. Report a
SUCCESS-with-message reply as an error. Give every failure a sequence number so the banner can re-arm.
This turns 03-02's red `errorPath.test.ts` green without touching its expectations (ERR-01, ERR-02,
ERR-04 server half, ERR-05 server half).

Purpose: ACK-AND-F3 section 4.2 item 1. The generic sentences replace the tool's text for
INVALID_ARGUMENTS and NOT_READY, which is the likeliest cause of the live "nothing on screen" report.
The code name is fixed at its source (D-13). The seq is the "small server change" D-15 accepts.

Output: pure `server/toolReply.ts` plus unit tests, a slimmer `tools.ts` reply path, a single
`_recordFailure` helper with `_failureSeq` in `command_queue.ts`, a plain-object `getError` with
`seq`, and three new static scans.
</objective>

## Deviations and resolved assumptions (recorded, not silent)

- **D-11 signature honoured literally:** `describeToolReply(command, toolId, reply)`, where `command` is the
  command name string. It lives in a new pure `server/toolReply.ts` (research suggested that file).
- **Whitespace-only text counts as empty (research A5, edge "ERR-02 empty"):** for the four generic codes,
  ERROR_FROM_TOOL and the default branch, "has text" means `error_message.trim().length > 0`. Text that has
  content is used verbatim, never trimmed. This changes today's output only for whitespace-only messages,
  which used to produce `Error from tool "x":    ` or a blank banner.
- **SUCCESS with a message (D-14, research A3 adopted):** it is handled exactly like an ERROR_FROM_TOOL reply
  with that message, giving code ERROR_FROM_TOOL and text `Error from tool "<id>": <text>`. A whitespace-only
  message gives the ERROR_FROM_TOOL empty sentence. D-14's "behaviour otherwise unchanged" is kept as its
  parenthetical defines it: the row FAILs and stays queued, and SUCCESS with an empty message is still success.
- **Seq seed (research A1):** `_failureSeq` starts at `Date.now()`, so a page open across a galago-web restart
  never holds a dismissed seq the new process reuses.
- **`_start` ordering scan placed here, not in 03-01:** 03-01 runs in wave 1 alongside 03-03, which owns
  `staticScan.test.ts` in that wave. This plan edits `_start` (the catch) and is the next owner of the scan
  file, so it adds the D-01 ordering scan.
