**Operator-text contract (the expected values this test pins; 03-04 implements it).** Command `transfer`, tool `fast-1`.
T is the tool's text. "blank" means `"   "` (spaces only). S_x is the generic sentence for code x, copied verbatim from tools.ts today:
- S_UNRECOGNIZED_COMMAND = `The command "transfer" is not recognized by the tool "fast-1". Please verify that this command is supported by this tool or page view.`
- S_INVALID_ARGUMENTS = `Invalid arguments provided for command "transfer". Check the parameters and try again.`
- S_NOT_READY = `The tool "fast-1" is currently not ready. Please wait and try again.`
- S_WRONG_TOOL = `The command was sent to the wrong tool type. Please check that you're using the correct tool for this operation.`
- E_EMPTY (ERROR_FROM_TOOL, no text) = `An error occurred while executing the command "transfer" on tool "fast-1".`
- D_EMPTY (default branch, no text) = `Failed to execute command "transfer" on tool "fast-1"` (no trailing period, as today)

| reply.response | message when T is non-blank | message when "" | message when blank | thrown/payload code |
|---|---|---|---|---|
| UNRECOGNIZED_COMMAND, INVALID_ARGUMENTS, NOT_READY, WRONG_TOOL | `S_x + " Tool said: " + T` | `S_x` | `S_x` | the same code |
| ERROR_FROM_TOOL | `Error from tool "fast-1": ` + T | E_EMPTY | E_EMPTY | ERROR_FROM_TOOL |
| DRIVER_ERROR, UNKNOWN_RESPONSE, UNRECOGNIZED | T | D_EMPTY | D_EMPTY | the same code |
| SUCCESS | `Error from tool "fast-1": ` + T | no error: row COMPLETED, getError null | E_EMPTY | ERROR_FROM_TOOL (never SUCCESS) |

Logs for every failing case: `"Tool Command Execution Error"`, level `error`, details exactly
`Failed to execute command: transfer, Tool: fast-1. Error: ${message} (Code: ${code})`. Then `"Command Failed"`, level `error`,
details exactly `Command failed: ${message}`.
getError payload for a tool failure: `{ message, userFriendlyMessage: message, code, codeString: code, name: "ToolCommandExecutionError", stack, seq }`.
