<objective>
Close UAT gap G-03-3: a FAILED or skipped-after-failure step card's error text must fit inside the fixed
165px card, and the sticky command label must never be drawn over it.

Root cause (binding, from .planning/debug/step-card-error-overflow.md): the card's content box is 151px
and already holds 147-148px of non-error content (header 40 + gap 8 + image 64/65 + gap 8 + label 27).
03-06 stacked the error Text under the image (+8px gap, up to +63px for 3 lines), so content reaches 218px
(scrollHeight 230 vs clientHeight 163) even a 1-line error overflows (188). Once the card overflows, the
background-less `position: sticky; bottom: 0` label pins to the scrollport bottom (card y 131-158) and
paints over the error lines until scrollTop ~60.

Fix route (from the diagnosis replica, measured): put the error Text in the same row as the command image
(image left, text right). The row height is the image's 64/65px, which absorbs the 63px clamped text, so
the card keeps its 147-148px content, never scrolls, and the sticky label stays inert in its flow slot.
Replica: no overflow for no error, 1-line and 3-line errors at 300px (text width 228px) and 250px (178px).

Purpose: ERR-03 / D-17 says the failed step's card shows its stored error; it must be readable on the card
without scrolling and never hidden under the label.

Output: the row reflow in SwimLaneCommandComponent.tsx, a new static-scan block that pins it, the
03-UI-SPEC.md S3 amendment, and the UAT test 3 retest as the plan's human check.

Gap-closure note: the phase tracer was 03-01. This plan's Task 1 is the single end-to-end slice of the fix
(persisted row -> stepErrorText -> card row -> fits); Task 2 records the contract change and runs the
phase gate.
</objective>
